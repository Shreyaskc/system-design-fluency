Glossary · precise definitions and practical meaning

Each entry gives an original precise definition, a plain-English meaning, a relatable analogy with its limit, and a concrete system example. Analogies aid intuition; the definition and explicit contract govern correctness. References support the stated technical concept, not the invented market examples. Sources checked 2026-10-19.

Invariant

Precise definition: A predicate over system state that is true initially and preserved by every permitted state transition.

Plain English: A rule the system must never break, including during competing requests and recovery.

Analogy and its limit: A shop cannot hand out more numbered collection tickets than it has allocated goods; unlike a physical counter, software copies can disagree.

Concrete example: If stock begins at five, accepting two reservations of three violates the nonnegative-stock invariant. Protect the decrement where authoritative state changes.

Herlihy and Wing: correctness and invariants · checked 2026-10-19.

Atomicity

Precise definition: A transaction property under which its participating state changes commit as one unit or have no committed effect.

Plain English: Either all the included database work counts, or none does.

Analogy and its limit: A sealed parcel contains every promised item or is not dispatched; the analogy does not make a separate courier transaction atomic.

Concrete example: Creating a reservation and decrementing inventory belong in one database transaction. A payment-provider call outside that database is not automatically rolled back with it.

PostgreSQL: transactions · checked 2026-10-19.

Isolation

Precise definition: The transaction property specifying permitted observations and interference among concurrently executing transactions.

Plain English: It controls how overlapping database operations may affect one another.

Analogy and its limit: Separate checkout desks can share inventory under different coordination rules; physical desk separation alone does not prevent selling the same last item.

Concrete example: Two transactions reading the same stock then writing independently can lose a decrement. Choose an atomic update or appropriate locking and isolation; merely writing BEGIN does not establish every desired guarantee.

PostgreSQL: isolation levels · checked 2026-10-19.

Linearizability

Precise definition: A concurrent-object correctness condition in which operations admit a legal sequential ordering, with each taking effect between invocation and response and respecting real-time precedence.

Plain English: Once a write finishes, a later read cannot behave as if that write has not happened.

Analogy and its limit: One authoritative ticket clerk assigns a single order to purchases; distributed implementations need not literally use one clerk.

Concrete example: After a stock update completes, a subsequent linearizable read observes it or a later valid update, rather than an old replica value.

Herlihy and Wing: linearizability · checked 2026-10-19.

Serializability

Precise definition: An isolation guarantee that committed concurrent transactions are equivalent to some serial execution of those transactions.

Plain English: Overlapping transactions produce a result possible if complete transactions ran one at a time.

Analogy and its limit: A manager can arrange whole order slips into an equivalent processing sequence; this does not require matching wall-clock completion order.

Concrete example: A multi-row inventory rule remains correct if every serial transaction preserves it. Serializable databases may abort conflicting attempts, so applications must retry the whole transaction safely.

PostgreSQL: serializable isolation · checked 2026-10-19.

Idempotency

Precise definition: The property that repeating an operation has the same intended effect on server state as applying it once, under the operation’s defined identity and scope.

Plain English: A retry should not multiply the business action.

Analogy and its limit: Presenting the same numbered collection ticket again does not earn another parcel; a new ticket represents a different request.

Concrete example: Repeated checkout requests reuse one shopper-scoped key and unchanged body. The service stores the result and rejects incompatible key reuse. Identical response bytes are not required, and protection needs a documented retention window.

RFC 9110 §9.2.2 · checked 2026-10-19.

Ambiguous outcome

Precise definition: A caller knowledge state in which available observations do not determine whether an operation committed or produced its external effect.

Plain English: No answer does not mean no action happened.

Analogy and its limit: A shopkeeper cannot hear whether a shouted collection request was fulfilled; shouting again may duplicate it. Unlike the analogy, software can preserve a durable request identity.

Concrete example: A provider captures payment but its response is lost. Keep the attempt pending, query or safely retry using its original identity, and reconcile before asserting failure.

RFC 9110: retries and method semantics · checked 2026-10-19.

Consensus

Precise definition: A distributed agreement problem requiring participating nodes to decide consistently on values despite a specified failure model, with progress under stated communication and availability assumptions.

Plain English: Nodes agree which decision counts, even when some stop responding.

Analogy and its limit: A committee records one approved motion; software protocols must also handle delayed messages and changing leadership, not human judgment.

Concrete example: A five-voter Raft group uses a majority of three. Three connected functioning voters can make progress under suitable timing assumptions; arbitrary malicious behavior lies outside Raft’s crash-failure model.

Raft: agreement and leader election · checked 2026-10-19.

Quorum

Precise definition: A subset of participants sufficient for a protocol step, chosen so required subsets intersect in ways the protocol’s safety argument needs.

Plain English: Enough relevant members must respond before an action counts.

Analogy and its limit: A committee may require three of five signatures; signatures alone do not specify how contradictory proposals are handled.

Concrete example: Two majorities of a five-node set overlap. That overlap helps consensus safety, but R + W greater than N alone does not prove linearizability without version, ordering, failure, and repair rules.

Raft: majority quorums · checked 2026-10-19.

Replication

Precise definition: Maintaining multiple copies of a dataset or state machine through a mechanism that propagates updates among copies.

Plain English: Keep other copies so one failure need not remove all usable data.

Analogy and its limit: Several shop ledgers copy each day’s changes; copying yesterday’s mistake reproduces the mistake rather than creating a backup.

Concrete example: A leader accepts a reservation while an asynchronous replica has not yet applied it. Reading that replica may show old stock. The acknowledgment and failover policy determine which acknowledged writes can survive a failure.

PostgreSQL: high availability and replication · checked 2026-10-19.

Partitioning / sharding

Precise definition: Partitioning divides a dataset into disjoint subsets; sharding typically assigns subsets to independently managed database nodes using a placement rule.

Plain English: Different owners hold different pieces of the data.

Analogy and its limit: Separate market stalls own different shelves; copying every shelf to another building would instead be replication. The analogy does not address cross-stall transactions.

Concrete example: Store identifier routes inventory to a shard. Shopper history may need a separate derived index. One popular item can still overload its owner. A network partition means broken communication, not this deliberate division.

PostgreSQL: table partitioning; cross-node sharding distinction is course terminology · checked 2026-10-19.

Backpressure

Precise definition: A flow-control mechanism by which downstream capacity constrains upstream production or admission of work.

Plain English: Slow down incoming work when the next stage cannot keep up.

Analogy and its limit: A cashier stops accepting baskets when the packing bench is full; a warehouse-sized waiting line only delays overload. Unlike people, software producers need explicit signals or enforced limits.

Concrete example: A bounded queue makes producers wait or reject work at capacity. If 250 jobs arrive per second and workers finish 150, backlog otherwise grows by 100 each second.

Java Flow: demand-based flow control · checked 2026-10-19.

Outbox

Precise definition: A durable event record committed atomically with business state and later published by an independent relay.

Plain English: Save the notification obligation with the change, then deliver it afterward.

Analogy and its limit: A shop staples a dispatch slip to the completed order record; a runner may copy a slip twice, so recipients still need duplicate handling.

Concrete example: An order and OrderConfirmed event commit in one transaction. A relay publishes the event and crashes before recording progress. It publishes again after restart; consumers deduplicate by stable event identifier.

AWS: transactional outbox · checked 2026-10-19.

Fencing token

Precise definition: A monotonically ordered ownership generation carried with operations and enforced by the protected resource to reject superseded owners.

Plain English: The storage system refuses commands from yesterday’s owner.

Analogy and its limit: A new supervisor receives a higher-numbered authorization badge; this works only if the warehouse checks the badge on every protected action.

Concrete example: Worker A pauses holding token seven. Worker B obtains token eight and writes. When A resumes, storage rejects token seven. Generating tokens without atomically enforcing them at the resource does not prevent stale writes.

Chubby: sequencers and stale lock holders · checked 2026-10-19.

Lease

Precise definition: A time-bounded grant of rights whose continued validity depends on a defined expiration and renewal protocol.

Plain English: You own permission for a limited time unless it is renewed.

Analogy and its limit: A market stall rental expires at closing time; the old tenant may still physically remain there. Software pauses likewise do not stop when permission expires.

Concrete example: A worker’s lease expires during a long pause. Another worker becomes owner, but the first can resume executing. Use resource-enforced fencing when stale execution could corrupt shared state, and state clock and timing assumptions.

Chubby: leases and sessions · checked 2026-10-19.

Watermark

Precise definition: A stream-processing progress indication describing how far event time is considered advanced under the system’s timestamp and lateness policy.

Plain English: The processor estimates which earlier time windows are ready to evaluate.

Analogy and its limit: A delivery clerk announces that the morning mail is probably complete; a delayed envelope can still arrive, depending on the policy. It is not a universal proof of completeness.

Concrete example: A five-minute order-count window closes when its watermark passes the boundary. A late offline order may trigger a correction, be retained separately, or be dropped according to the documented rule.

Flink: event time and watermarks · checked 2026-10-19.

SLI / SLO

Precise definition: A service level indicator quantifies a service behavior; a service level objective specifies a target for that indicator over a defined population and time window.

Plain English: Measure what users experience, then state how good it should be.

Analogy and its limit: A grocer measures the fraction of collections ready on time and sets a target; unlike a vague promise, the measurement needs eligibility and timing rules.

Concrete example: Count eligible catalog requests returning a correct result within 300 milliseconds, targeting 99.9 percent over thirty days. A process health check measures something narrower.

Google SRE: indicators and objectives · checked 2026-10-19.

RPO / RTO

Precise definition: Recovery point objective specifies targeted maximum data loss measured backward in time; recovery time objective specifies targeted maximum time to restore the defined service after disruption.

Plain English: How much recent work may be lost, and how long recovery may take.

Analogy and its limit: A shop can reconstruct sales only to its last copied ledger and needs time to reopen; software recovery also includes routing, credentials, and validation.

Concrete example: A five-minute RPO and thirty-minute RTO require a tested procedure that restores sufficiently recent data and usable service inside those targets. Objectives are not demonstrated achievements.

AWS Well-Architected: disaster recovery objectives · checked 2026-10-19.

p99 latency

Precise definition: The ninety-ninth percentile of measured operation durations for a specified population, observation boundary, interval, and percentile calculation convention.

Plain English: Approximately ninety-nine percent of measured operations finish at or below that duration.

Analogy and its limit: In a sorted line of one hundred collection times, look near the slow end rather than the average; real percentile estimators need not select exactly one sample.

Concrete example: A 300-millisecond server p99 excludes client-side connection failures unless measured there. Adding three dependencies’ p99 values does not give the request p99 because their slow observations may differ.

Google SRE: latency distributions and measurement · checked 2026-10-19.

CDN

Precise definition: A content delivery network distributes content-serving infrastructure across network locations, commonly caching origin responses nearer consumers.

Plain English: Serve reusable bytes from a nearby copy instead of the main application each time.

Analogy and its limit: Neighborhood collection lockers save everyone a trip to the central shop; a locker does not decide whether a customer is entitled to a private parcel.

Concrete example: A product image with a versioned public URL can be cached at edge locations. Private order receipts need deliberate authorization and cache policy. Proximity can improve delivery without guaranteeing the newest origin state.

RFC 9111: shared-cache behavior; CDN example is illustrative · checked 2026-10-19.

TTL

Precise definition: Time to live is a configured validity or retention duration whose exact start point and expiration behavior depend on the protocol or storage system.

Plain English: An entry has a time limit, under specific rules.

Analogy and its limit: A price label marked valid for sixty seconds expires, but replacing it with an already old label does not make the price current.

Concrete example: A cache entry written from a lagging replica can expire sixty seconds after insertion yet describe an older fact. State whether expiration triggers deletion, revalidation, or refusal; TTL alone does not eliminate stale-fill races.

RFC 9111: freshness lifetime and age · checked 2026-10-19.

Fanout

Precise definition: Expansion of one input operation or event into multiple downstream deliveries, requests, or materialized updates.

Plain English: One thing happening creates work for many destinations.

Analogy and its limit: A grocer sends one sale announcement to every subscriber; the analogy hides failures and duplicate deliveries that software must handle explicitly.

Concrete example: A post with ten thousand followers may create ten thousand inbox updates with fanout-on-write, or be combined into feeds during reads. Large follower skew changes the cost. Define whether partial delivery, retries, ordering, and duplicate recipients are acceptable.

RabbitMQ: fanout exchange publish/subscribe example · checked 2026-10-19.

Cursor pagination

Precise definition: A pagination method that resumes traversal from an encoded position in a defined ordering, often using the last observed ordering key.

Plain English: Continue after where you stopped instead of skipping a count of rows.

Analogy and its limit: A bookmark identifies the last shelf position visited; rearranging shelves can still change the next page. The bookmark alone does not freeze the catalog.

Concrete example: Order history sorts by created_at and unique order_id, returning the last pair in an opaque cursor. Specify snapshot behavior and use a unique tiebreaker. Large OFFSET queries otherwise compute skipped rows.

PostgreSQL: ordering and OFFSET costs; cursor design is the course example · checked 2026-10-19.

Observability

Precise definition: The capacity to infer relevant internal system behavior from externally available outputs and telemetry.

Plain English: Have enough useful evidence to explain what happened and why.

Analogy and its limit: A grocer combines till totals, delivery notes, and queue observations to diagnose a delay; collecting more paper without a question does not improve understanding.

Concrete example: Metrics show rising checkout failures, traces locate slow inventory calls, and correlated logs explain lock contention. Include business outcomes and careful sampling. Telemetry that leaks personal data or cannot connect request stages creates new problems rather than sufficient visibility.

OpenTelemetry: observability and telemetry signals · checked 2026-10-19.

Training-serving skew

Precise definition: A mismatch between the features, transformations, distributions, or data availability used during model training and those encountered when serving predictions.

Plain English: The model is taught with a view of the world different from the one it gets in use.

Analogy and its limit: A grocer trains assistants using tomorrow’s complete demand report, then asks them to predict today with partial information; real models can also differ through code and pipelines.

Concrete example: Training computes a seven-day purchase count using future-complete data, while online inference uses delayed events. Use point-in-time joins, shared definitions, freshness checks, and comparison monitoring.

Google: Rules of Machine Learning, training-serving skew · checked 2026-10-19.
