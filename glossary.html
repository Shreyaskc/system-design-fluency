Glossary · terms with operational meaning

Definitions are contracts to reason with, not vocabulary to recite. Tap a term in the lessons for a definition where provided. This page remains available without JavaScript.

Invariant

A condition that must remain true after every permitted state transition, such as stock never becoming negative.

Atomicity

A set of state changes is committed together or has no committed effect. It does not automatically include an external API call.

Isolation

Rules controlling what concurrent transactions can observe and how their operations interact.

Linearizability

Each operation appears to take effect at one point between its call and response, respecting real-time ordering.

Serializability

Committed transactions have an outcome equivalent to some serial order; that order need not preserve real-time ordering.

Idempotency

Repeating the same logical operation has the same intended effect as performing it once. The identity and retention window must be defined.

Ambiguous outcome

The caller cannot determine whether an operation committed, often because the response was lost after a timeout.

Consensus

A protocol for participating nodes to agree on decisions despite specified failures. Raft assumes crash failures, not arbitrary malicious behavior.

Quorum

A required subset of participants. Majority quorums overlap, but quorum arithmetic alone does not define a complete consistency protocol.

Replication

Maintaining copies of state for failure tolerance or read scale. An asynchronously updated copy can lag.

Partitioning / sharding

Dividing data across owners using a key or range. This is different from a network partition, where nodes cannot communicate.

Backpressure

A downstream consumer signals or enforces a limit on upstream production so overload does not accumulate without bound.

Outbox

An event record stored in the same database transaction as business state, then relayed asynchronously. Relays can duplicate events.

Fencing token

An increasing ownership epoch checked by the protected resource to reject writes from superseded workers.

Lease

Ownership granted for a bounded period. Expiration does not stop an already running process; fencing may still be needed.

Watermark

A stream processor’s progress estimate about event-time completeness, governed by a lateness policy rather than a guarantee that no older event can ever arrive.

SLI / SLO

A service level indicator measures user-visible behavior. A service level objective sets its target over a stated window.

RPO / RTO

Recovery point objective bounds acceptable data loss in time. Recovery time objective bounds the intended restoration time.

p99 latency

The 99th percentile of observed durations at a specified boundary and window. It is not the mean and is not additive across dependencies.

CDN

A content delivery network places cacheable content near clients; cache keys, expiry and authorization still matter.

TTL

Time to live: an expiry duration. A TTL may bound age under a defined protocol, but does not by itself solve every invalidation race.

Fanout

Expanding one event into work for multiple recipients; the degree and skew determine its cost.

Cursor pagination

Continuing a query from a stable ordering position, commonly a tuple such as created_at and unique ID, rather than skipping an offset.

Observability

Inferring system behavior from emitted signals such as metrics, logs and traces. Signals must be tied to useful operational questions.

Training-serving skew

A mismatch between features or transformations used to train a model and those used during online inference.
