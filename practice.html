LESSON 26 / 27 · ORIGINAL TEACHING EXAMPLES

Practice · failure probes and self-assessment

Use a 45-minute timer for a full case, or five minutes for one failure probe below. Write your answer before opening the sample. These are original exercises; sample answers show a defensible direction rather than a universal architecture.

Probe 1: A response is lost after an order commits. Show a safe retry protocol.

Reveal sample reasoning

Persist a client-scoped idempotency key, request fingerprint and outcome in the same transaction as the order. Retry the same key. Reject changed payloads. Return the stored outcome; expire keys only after defining the retry window. A volatile cache alone cannot protect a durable side effect.

Probe 2: Two requests each observe one remaining item. Both purchase it. Identify the broken invariant and repair it.

Reveal sample reasoning

The invariant is reserved quantity plus sold quantity never exceeding stock. A read followed by an unconditional update permits both reads before either write. Use a conditional atomic decrement and check affected rows inside the reservation transaction. Add a unique request key. A Python mutex in one replica does not protect another replica.

Probe 3: A cache says a user may see a private photo. Permission has just been revoked. What happens?

Reveal sample reasoning

Revocation is a security boundary. Do not authorize from a potentially stale content cache. Re-check authoritative permission or a versioned policy with an explicitly bounded revocation contract; invalidate delivery credentials and caches as needed. A short expiry reduces exposure but does not meet immediate revocation.

Probe 4: At 1,000 requests/s with 200 ms mean time in system, how many requests are in flight?

Reveal sample reasoning

At stable load Little’s law gives L = λW = 1,000/s × 0.2 s = 200. This uses averages at the same boundary, not p99 latency. It does not imply 200 CPU cores. Queueing, downstream connections and asynchronous waits matter.

Probe 5: A worker completes an email then crashes before acknowledging. Can the queue guarantee no duplicate email?

Reveal sample reasoning

Redelivery can repeat the email. A queue cannot make its acknowledgment atomic with an arbitrary mail provider. Use a provider-supported stable deduplication key, or accept possible duplicates with a durable attempt ledger and reconciliation. A local done flag written after sending retains the crash window.

Probe 6: A five-node consensus group loses three nodes. May two survivors accept writes?

Reveal sample reasoning

A majority is three. Two cannot safely elect a leader and commit new entries under the assumed Raft model. Serve only reads whose semantics are justified; a stale read must be labeled as such. Restoring availability by forming a new cluster without a recovery protocol risks losing acknowledged state.

Probe 7: A seller with ten million followers posts. Your feed uses write fanout. What changes?

Reveal sample reasoning

Ordinary-seller assumptions no longer bound fanout cost. Use a hybrid: precompute ordinary feeds and merge high-fanout sellers at read time. Preserve a durable post log, deduplicate by post ID, cap work per request and define freshness under backlog. The threshold comes from measurements, not an arbitrary celebrity number.

Probe 8: A search index still contains a deleted listing. How do you meet a five-second deletion requirement?

Reveal sample reasoning

Index removals through a durable versioned event, measure propagation lag, and filter against a deletion tombstone or current visibility check at serving time. Replay must not resurrect older versions. A periodic full rebuild alone cannot bound deletion latency.

Probe 9: A schedule fires twice after a lease timeout. Explain fencing.

Reveal sample reasoning

A fencing token is a monotonically increasing ownership epoch. Each mutation to the protected resource includes it; the resource rejects older epochs. Lease expiry alone cannot stop a paused worker from waking up. External effects still need their own idempotency or fencing support.

Probe 10: An active-active inventory design merges counters after a network partition. Is overselling prevented?

Reveal sample reasoning

No: both regions can spend the same remaining unit. Route ownership to one region, use coordination and reject unavailable writes, or allocate non-overlapping bounded stock rights to each region. Reconciliation detects an oversell after the fact; it does not preserve the invariant.

Probe 11: A streaming count changes after late events. Is the old answer wrong?

Reveal sample reasoning

Define event time, allowed lateness and whether results are provisional. Emit revisions or an explicit finalization boundary. Deduplicate stable event IDs for the agreed retention window. Keep source records for replay and reconcile against batch totals. Different windows and correction rules can both be valid if the contract is explicit.

Probe 12: Feature serving is fast, but recommendations degrade after deployment. Where do you investigate?

Reveal sample reasoning

Check feature version, freshness, missingness and training-serving transformation agreement before adding hardware. Pin model and feature schema versions, compare offline and online values, and canary with quality and operational guardrails. Safe fallback may be a non-personalized ranking; low latency alone does not imply correct predictions.

A reusable scoring sheet

Score each dimension 0 (missing), 1 (named), 2 (defended with a concrete trace), or 3 (survives a changed assumption): scope; units and capacity; API/data contract; correctness; failures/recovery; operations/security; alternatives/cost; communication. This is a learning rubric, not an employer hiring rubric. A total can hide a dangerous correctness gap: repeat any case whose invariant or acknowledgment boundary scores below 2.

For principal practice add evidence for migration ownership, organizational interfaces, failure containment, measurable decision triggers and reversal cost. Ask a partner to change one requirement halfway through. Record whether you adapt using evidence or merely add components.
